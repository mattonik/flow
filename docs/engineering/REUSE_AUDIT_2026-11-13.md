# Flow reuse-first audit — 13 November 2026

This audit applies [the reuse-first atlas](REUSE_FIRST_REFERENCE_ATLAS.md) alongside [the master specification](../Flow_MASTER_SPEC_v1.1.md). Architecture remains NixOS + Niri + Quickshell, with a separate, versioned, toolkit-independent Flow Controller/API; touch is a first-class requirement. No Flow `AGENTS.md` was found in this checkout, its parent folders, or `origin/main` during the audit; do not treat an upstream project's agent instructions as Flow policy.

Flow revision audited: `90c9c452a0d690204752721bc2755d98e1e3ed2e`; pinned nixpkgs `f4a03c008967841f2a0b3cb7c436fc6fc31671f6`. The aarch64 package metadata evaluated successfully on the host; this proves availability and metadata, not a Linux build or runtime. Existing guest evidence is from [milestones](../milestones.md), not a new acceptance run. No candidate below was installed or benchmarked in Flow for this audit. Source revisions inspected: Pond `9277356200ac02c5367587bc7b68a079cb2574e7` (BSD-3-Clause), Omarchy `ac6cb9c712848741f994d7ecbaccdbab90b526e8` (MIT at repository level). Check file headers, bundled assets, dependency licenses and trademarks before reuse. This Flow checkout has no tracked license file; settle project licensing before copying code.

Evidence labels: **Flow verified** = existing behavior exercised in its ARM64 VM as recorded; **source verified** = real upstream implementation inspected, not tested with Flow; **candidate** = proposed integration not demonstrated in Flow. Estimates below are rough engineering sizing, not measured delivery times, and include neither device procurement nor complete accessibility/security acceptance.

## Current repository: keep, replace, or investigate

- **Already reusing:** Niri's compositor and overview, Quickshell, Fuzzel, Gio/XDG app launch, NetworkManager, WirePlumber commands, swaylock/swayidle, and Nautilus. These are appropriate foundations; retain them until a replacement passes the same journeys. Single-window pins, basic audio, Niri events, lock and recent-file launch have recorded VM evidence. Full portals, actual touch and multi-display are not established.
- **Duplicated infrastructure:** `session/shell.qml` listens to Niri events but refreshes by repeatedly invoking `flow-spaces`, whose `snapshot()` runs three Niri queries; `search.py` also invokes a refresh and builds app/file rows each time. `restore.py` and `spaces.py` each implement Niri/state orchestration. Replace duplicate state acquisition only after an adapter proves reconnect and consistency; retain the Flow-specific semantic model and cautious restoration behavior.
- **Polling:** the shell polls audio/network subprocesses every four seconds while Quick Settings is open. This is a small working prototype, not a custom audio/network stack; event-driven service access can remove repeated parsing and give accurate external updates. Measure before claiming a performance win.
- **Custom search:** Fuzzel and Gio are reused, but `session/search.py` hand-parses a capped recent-file XBEL and makes a one-shot result list. Keep its privacy checks, pin/focus routing and current fallback while assessing established file search and launch components. Recent history is not full file search.
- **Unimplemented capabilities:** notification history, Bluetooth, actual network connection controls and portals are missing; they are not existing custom replacements. Adopt service-backed components before writing competing daemons.
- **Flow-specific work remains:** semantic Group identity, pinned-space intent, restoration policy, display anchoring, Desk/Island presentation, focus security and adaptive touch interactions are not supplied by Niri's window indices. Do not drop these merely because another shell offers workspaces.
- **Immediate hardening:** `FlowButton` renders dynamic window names in QML `Text` without explicitly setting `Text.PlainText`. Inspect all app-controlled labels/errors and ensure plain text before copying other shell UI; test markup-shaped titles. Omarchy's [plugin guidance](https://github.com/omacom/omarchy/blob/ac6cb9c712848741f994d7ecbaccdbab90b526e8/default/agents/skills/omarchy/plugins.md) explicitly warns about QML AutoText. Treat in-process QML as trusted code, never as a sandbox.

## Prioritized recommendations

### 1. Niri state adapter — PROTOTYPE, P0

**Reuse:** [Niri IPC and event-stream](https://github.com/niri-wm/niri/blob/main/docs/wiki/IPC.md), plus [Pond's NiriMsg](https://github.com/bflycomputer/pond-interface/blob/9277356200ac02c5367587bc7b68a079cb2574e7/shell/NiriMsg.qml) and [minimap drag handling](https://github.com/bflycomputer/pond-interface/blob/9277356200ac02c5367587bc7b68a079cb2574e7/shell/minimap/DragSession.qml) as concrete references. Pond maintains event-derived workspace/window state, reconnects its event stream and performs Niri actions; it is **source verified**, not verified in Flow. It also has Pond-specific imports, launcher behavior and drag assumptions. Flow's event stream and separate snapshot queries are **Flow verified** at prototype level.

**Recommendation:** prototype a single controller-owned event projection using Niri's supported IPC or version-matched `niri-ipc`; keep Flow semantic IDs and recovery separate and leave the QML shell as a client. Do not adopt Pond's whole QML singleton as the authoritative cross-toolkit API. **License:** Niri 26.04 package metadata GPL-3.0-only; Pond BSD-3-Clause, retain notices when copying. Linking/distribution implications and a Flow license require review. **Effort:** medium to high. **Limitations:** Niri IPC version coupling, missed/reordered events, restart and outputs, no proven persistent semantic Groups, touch or generic drag. **Next test:** run old snapshot path and candidate side by side on the ARM64 guest; compare window/focus/output state across open/close, focus, shell/controller restart and compositor disconnect, log process count and CPU. Add a hardware touch/rotation test before asserting tablet support.

### 2. Audio and quick settings — PROTOTYPE, P0

**Reuse:** Quickshell's [PipeWire service](https://quickshell.org/docs/v0.2.1/types/Quickshell.Services.Pipewire/Pipewire/), [Pond audio state](https://github.com/bflycomputer/pond-interface/blob/9277356200ac02c5367587bc7b68a079cb2574e7/shell/audio/State.qml), and [Omarchy's media service](https://github.com/omacom/omarchy/blob/ac6cb9c712848741f994d7ecbaccdbab90b526e8/shell/plugins/services/media/Service.qml). These are **source verified**; Flow's `wpctl` volume change is **Flow verified**, while its proposed replacement is untested. Prefer Quickshell's own service over copying an entire foreign panel.

**License:** pinned Quickshell 0.3.2 package LGPL-3.0-only; Pond BSD-3-Clause; Omarchy MIT at repository level. Assess plugin-specific notices and linked dependencies. **Effort:** low to medium. **Limitations:** null sinks, device changes, mute/volume semantics, microphone privacy, service restarts and touch; upstream docs linked above cover 0.2.1, so verify the API against pinned 0.3.2. **Next test:** isolated QML probe in the VM, compare external `wpctl` updates, mute and default-sink changes, disconnect/reconnect; verify touch target sizes and keyboard access, compare CPU and subprocess count, retain current controls until equivalent.

### 3. Network, Bluetooth and power — WRAP established services, P0

**Reuse:** NetworkManager D-Bus / NetworkManagerQt, BlueZ, UPower and logind, with [Pond's Wi-Fi](https://github.com/bflycomputer/pond-interface/blob/9277356200ac02c5367587bc7b68a079cb2574e7/shell/wifi/State.qml) and [Bluetooth](https://github.com/bflycomputer/pond-interface/tree/9277356200ac02c5367587bc7b68a079cb2574e7/shell/bluetooth) as **source-verified** references. Pond's network code uses `/usr/bin/nmcli` and its project requires Qt 6.12 and KF6NetworkManagerQt; neither is a demonstrated fit for this pinned VM. Flow's connectivity status is a basic existing client, not a full network stack.

**License:** nixpkgs metadata: NetworkManager GPL-2.0-or-later; BlueZ mixes BSD-2-Clause, GPL-2.0-or-later, LGPL-2.1-or-later and MIT; Pond BSD-3-Clause. Check each linked library and service separately. **Effort:** medium per domain, Bluetooth pairing and hardware higher. **Limitations:** authorization agents, secrets, VPN plugins, pairing confirmation and unavailable devices; do not copy `/usr/bin` assumptions or expose credentials to QML/CLI logs. **Next test:** use a separate opt-in NixOS configuration to read a live NetworkManager signal and open the system's existing network tool; test failure/offline feedback, portrait and touch; on physical hardware test BlueZ pair/unpair with a disposable device. Keep `nmcli` fallback for diagnostics.

### 4. Notifications — PROTOTYPE, P0

**Reuse:** [Quickshell notification server](https://quickshell.org/docs/types/Quickshell.Services.Notifications/NotificationServer/) and [Pond's notification state](https://github.com/bflycomputer/pond-interface/blob/9277356200ac02c5367587bc7b68a079cb2574e7/shell/notifications/State.qml); compare a packaged [Mako](https://github.com/emersion/mako) fallback. Pond's real history and server implementation is **source verified**, not Flow verified. Current Flow has no notification history.

**License:** Quickshell LGPL-3.0-only in pinned metadata, Pond BSD-3-Clause, Mako MIT in pinned metadata. **Effort:** medium. **Limitations:** exactly one session notification owner, actions and DND, private content storage and redaction, shell crashes, lock-screen visibility; touch and accessibility need proof. **Next test:** run a disposable session with one server only; send actionable and transient test notifications, exercise DND, shell restart and screen lock; inspect per-user persisted data and disable/rollback behavior. If embedded server fails, keep a separately configured Mako fallback.

### 5. File search and application launcher — EVALUATE, P1

**Reuse:** retain **Flow-verified** Fuzzel/Gio launcher and current XBEL fallback; evaluate [GNOME LocalSearch](https://gnome.pages.gitlab.gnome.org/localsearch/) for opt-in metadata indexing and [Vicinae](https://github.com/vicinaehq/vicinae) as a launcher reference (Pond has its [own fork](https://github.com/bflycomputer/vicinae)). Both `localsearch` 3.12.0 and `vicinae` attributes exist in pinned aarch64 nixpkgs; evaluation is not a build or compatibility test. Neither is Flow verified.

**License:** LocalSearch GPL-2.0-or-later in pinned metadata; Fuzzel MIT/Zlib; Pond's Vicinae fork reports GPL-3.0; verify chosen upstream version, dependencies and distribution obligations before integration. **Effort:** medium to high. **Limitations:** desktop-service dependencies, indexer CPU/battery, storage, home/exclusion policy, permissions, service ownership, Fuzzel's touch UX and UI responsiveness. Preserve current per-user boundaries and do not silently index private data. **Next test:** opt-in isolated test user, seed named files including excluded/private paths, measure cold/warm results and idle resources, disable/remove index and verify sandbox access. Test a large touch target/keyboard Flow front end before replacing Fuzzel; preserve Flow spaces and settings providers.

### 6. File manager and portals — ADOPT existing app; RESEARCH Flea, P1

**Reuse:** Nautilus is **Flow verified** as a real app. [Dolphin](https://apps.kde.org/dolphin/) exists as `kdePackages.dolphin` in the pinned aarch64 package set but is not independently verified here. [Flea](https://github.com/thisisgm/flea) is an actual MIT-licensed upstream project with separate third-party licenses and an Omarchy-oriented install path; its NixOS/Niri/ARM64/touch support is a **candidate**, not a Flow result. The `flea` top-level attribute was absent from this particular pinned nixpkgs evaluation; this does not rule out other packaging.

**License:** Dolphin has mixed GPL/LGPL/BSD/MIT/CC0 metadata; Flea repo MIT plus its third-party manifest; portal package metadata varies (pinned `xdg-desktop-portal-gnome` LGPL-2.1-or-later). **Effort:** low to configure a tested existing manager, high for Flea port and chooser. **Limitations:** network mounts, file chooser backend ownership, sandbox permissions and touch; do not change default handlers for an experimental build. **Next test:** retain Nautilus, build Flea in an isolated Nix derivation without Omarchy scripts; test launch, sandbox Open/Save, cross-app drag, folder mounts and portrait/touch using the [XDG portal interfaces](https://flatpak.github.io/xdg-desktop-portal/docs/). Roll back by disabling the candidate module.

### 7. Capture and secure session — EVALUATE, P1

**Reuse:** keep **Flow-verified** swaylock and system-requested lock. For capture use Niri's own screenshot action and supported [XDG Screenshot/ScreenCast portals](https://flatpak.github.io/xdg-desktop-portal/docs/), then evaluate existing annotation tools such as [Omasnap](https://github.com/omacom/omasnap), rather than a custom capture backend. Candidate support under Niri has not been established. **License:** inspect each package's full metadata; Omasnap repository reports MIT, but review dependencies/assets. **Effort:** low to medium for portal configuration, medium to high for tested full workflow. **Limitations:** focus stealing, output selection, Wayland permission prompts, sandbox and app compatibility, no guaranteed Niri support for Omarchy-specific paths. **Next test:** disposable file-picker/screenshot/screencast matrix with a native and sandboxed app; verify cancel/deny, share indicator, clipboard, touch and lock/unlock; retain current locker.

### 8. Touch and adaptive Groups — INVESTIGATE upstream first, P0/P1

**Reuse:** Niri scrolling/layout primitives and its event stream; Pond's [minimap](https://github.com/bflycomputer/pond-interface/tree/9277356200ac02c5367587bc7b68a079cb2574e7/shell/minimap) is an actual pointer/drag reference, not evidence of touch or adaptive Group behavior. Keep Flow's distinct semantic Group model and API. **License:** Niri GPL-3.0-only package metadata; Pond BSD-3-Clause; reuse notices and dependencies apply. **Effort:** high; hardware-dependent. **Limitations:** VM pointer tests do not prove multi-touch, edge arbitration, IME, rotated coordinate mapping or continuity. **Next test:** on a supported touch device, record Niri/Qt event behavior for single touch, multi-finger gestures, OSK/IME and rotation while two real apps are grouped; compare upstream capabilities and file a targeted upstream issue or patch only for demonstrated gaps. Maintain keyboard/mouse fallback and don't claim Flow touch support from a mock.

## Proposed execution order

1. Fix plain-text rendering and establish a reproducible event/CPU baseline; no third-party integration needed.
2. Prototype one controller-owned Niri event projection, preserving existing behavior and API/security boundaries.
3. Build a minimal Quickshell PipeWire probe alongside the existing volume control; compare actual behavior before replacing polling.
4. Choose notifications or NetworkManager as the first complete service-backed vertical slice with an accessible touch-ready surface, isolated tests and a rollback.
5. Separately test portals and touch/rotation on actual hardware. Keep file-manager and indexer experiments opt-in and maintain a working fallback.

This is an audit and proposed test plan, not approval to replace components or evidence of real-hardware support.
