# Floe (formerly Flow)

**Floe** is the product identity; **Flow** remains the horizontal interaction model and the current internal service/configuration name. Explore [Arctic Minimalism](design/BRAND_GUIDELINES.md) and the [interactive dark/light identity preview](design/preview/index.html). The shell uses the new appearance tokens; this is **not** a full-system theme.

Flow is an experimental, multiplatform Linux session. Product intent is in [the unmodified v1.1 master specification](docs/Flow_MASTER_SPEC_v1.1.md), with [contextual menu direction](docs/Flow_contextual_menus_groups.md). The [v1.0 product brief](docs/Flow_product_brief_v1.0.md) is retained, and the [v1.0 HTML prototype](docs/Flow_v1.0_Contextual_Menus.html) is a design reference, not a native implementation. iPad enablement is a separate project.

**Status: foundation only, not a working MVP.** A single-display ARM64 UTM guest has run the Niri session, Quickshell island, app launcher and two terminal windows; see [graphics validation](docs/graphics-validation.md). Pinned spaces are an experimental single-display implementation; other MVP requirements remain incomplete. See the [acceptance status](docs/IMPLEMENTATION_STATUS.md) and [milestones](docs/milestones.md).

For a short walkthrough using real applications, see [Recording a Flow demo](docs/demo.md). Engineering guidance and reuse opportunities are in the [reuse-first atlas](docs/engineering/REUSE_FIRST_REFERENCE_ATLAS.md) and [reuse audit](docs/engineering/REUSE_AUDIT_2026-11-13.md).

## First: validate the graphics path

Use a disposable ARM64 NixOS guest in UTM's **QEMU** backend with a VirtIO GPU GL/3D-accelerated display. The Apple Virtualization backend is a different graphics path and is not the target of this test. UTM settings and capabilities vary by version. See [UTM's graphics architecture](https://github.com/utmapp/UTM/blob/main/Documentation/Graphics.md) and [Niri's VM guidance](https://github.com/niri-wm/niri/wiki/Getting-Started).

Before installing Flow, enable `programs.niri.enable = true;` and `hardware.graphics.enable = true;` in the guest, install `mesa-demos` and `wayland-utils`, rebuild, and sign into a plain Niri session. In a terminal run `glxinfo -B` (if XWayland is running) and `eglinfo -B`; record the renderer, versions, UTM backend, GPU settings and guest versions. Confirm the renderer is accelerated (not llvmpipe/softpipe), that the active DRM device is the intended VirtIO GPU, and that a real Wayland app opens and moves smoothly. Capture relevant `journalctl --user -b` and compositor errors. A GL device setting alone is not evidence of guest acceleration. Record the outcome in [graphics validation](docs/graphics-validation.md). If Niri fails, stop and diagnose the guest graphics stack before claiming Flow works.

## Install on an existing NixOS guest (after graphics validation)

Add this repository as a flake input to the guest's existing NixOS flake, then add `inputs.flow.nixosModules.default` to the target system's `modules` list and set `services.flow.enable = true;` in that system's configuration. Keep the guest's existing boot, filesystems, networking, account, display-manager and hardware configuration. When combining Niri with Plasma, set `services.displayManager.defaultSession = "plasma";` (or `"niri"`) explicitly to resolve their competing defaults. `nixos-rebuild build --flake .#HOST` first; then `sudo nixos-rebuild switch --flake .#HOST` and select Niri at login. Back up configuration and know how to select the previous NixOS generation before switching. This module installs a system-wide `/etc/niri/config.kdl`; a user's existing `~/.config/niri/config.kdl` takes precedence. It also installs a Fuzzel default. Review both before enabling it on an existing machine.

Flow's shell uses the stable path `/etc/flow/shell.qml` so its shortcuts continue to address the running shell when a new system generation changes the underlying Nix store path. When upgrading from a version that used a store path directly, sign out and back in once or restart the Flow shell to adopt the new identity.

The initial session uses Niri's horizontal columns and real Linux apps. `Super+Left/Right` navigates between logical spaces, `Super+Up/Down` focuses Group members, `Super+Return` opens a terminal, `Super+K` searches recent files, Flow settings, installed apps, open windows and pinned spaces, `Super+I` opens quick settings, `Super+Tab` opens the bottom window switcher, `Super+O` opens Niri overview, `Super+H` toggles the Desk, `Super+L` locks, and `Super+Shift+/` shows shortcuts. `Super+Shift+E` quits the session. The Desk offers search, files, a notification inbox and a return to work; it overlays existing windows rather than closing them. Apps and Notifications open over the Desk, which stays visible until you launch an app or return to work. Pin the current single-window app with `Super+P` or the Desk button, select a pin from the Desk or with `Super+1`–`Super+9`, and choose **Edit pins** to reveal the arrow and × buttons for reordering or unpinning. Desk buttons support Tab and Enter or Space; Escape returns to work. The capsule shows an app-picker control, the local clock and quick settings for network connectivity and output volume, with live audio updates through Quickshell’s PipeWire service; the Apps control opens the launcher. Click an application outside the launcher to dismiss it, or choose **Close** in the Island; Escape also works. The Desk is an early product surface. Search covers recent local files within the user’s home folder, Flow settings, quick settings, installed applications and windows and pins on the current workspace. Closed pins can be reopened from search when their application is available. Recent files come from the user’s existing recent-file history; there is no full file index or app-command search yet. The separate Apps launcher still lists installed desktop entries. Fullscreen and broader input behavior need guest verification.

Quick Settings includes **Edit connections**, which opens NetworkManager's existing connection-profile editor. Selecting or activating Wi-Fi networks from Flow and touch operation remain to be implemented and tested; `nmtui` is available as a keyboard-only fallback on NetworkManager systems.

When exactly one controllable MPRIS player can be identified, Quick Settings shows its current track and a Play/Pause control. If several players are ambiguous, the control is hidden until the selection is unambiguous. Availability depends on the media application exposing MPRIS.

Flow starts swayidle to handle system lock requests and requests a lock before suspend. `Super+L` can also restart the locker if it crashes while the compositor remains locked. Manual and system-requested locking and password unlock have been checked in the UTM guest; suspend/resume and automatic idle locking have not been verified, and no idle timeout is configured.

The bottom handle opens a horizontally scrollable list of the current workspace’s open windows; select one to focus it, or press Escape to dismiss it. Keyboard focus scrolls the selected control into view; when the list overflows, arrow buttons move through it by page. This first version shows window names, not live previews, and has not yet been validated for touch or multiple displays. The switcher also opens Niri’s live overview of the workspace. It can stack the active tiled window with the next window on its right and separate a two-window stack again. `Super+Up/Down` changes focus within a stack. The switcher shows a stack as one space and offers a focus button for each member. Both windows must be unpinned. For an active two-app stack, choose **Create Group**, then use **Rename Group** to change its name. **Dissolve Group** separates an unpinned Group without closing its apps. **Tabs / stack** changes the active stacked Group between Niri's tabbed and vertical-stack views. **Side by side** and **Stack** explicitly switch a two-app Group between layouts while keeping one switcher destination and any existing pin. Automatic rotation is not implemented.

**Session recovery is experimental.** Before restarting, save your documents in their applications, open the Desk, choose **Settings**, and choose **Save session**. After signing in to Niri, open the same settings and choose **Restore session**. Flow records the current workspace's ordered window list and focused app in `~/.local/state/flow/session.json`, and retains the snapshot until you explicitly save again. After saving, it warns about windows with duplicate or missing application IDs, missing desktop entries, or floating/untiled layouts that require manual recovery. It tries to relaunch each missing app through its exact installed desktop entry, order unique single-window apps, and restore focus. A saved two-window stack can be re-formed when both unpinned apps resolve uniquely as single tiled windows; Flow moves them together if necessary and checks their positions before stacking. Existing valid stacks are retained. When every saved window and Group is available and no pinned app is on the workspace, recovery can also restore their mixed column order. Otherwise it reports when that ordering needs manual attention. Recovery stops if it detects that the focused workspace changed; already launched apps remain open. The result reports applications or stacks that need manual recovery. Existing pinned-space metadata is stored separately.

Within the same compositor session, recovery can identify multiple still-open windows of one app by their saved window IDs. After the compositor restarts, those IDs are not trusted: multiple windows of the same app need manual recovery. Group names and identities are stored independently in `$XDG_STATE_HOME/flow/groups.json` (normally `~/.local/state/flow/groups.json`); existing snapshot Groups migrate on first use. Session snapshots remain separate. The switcher lists incomplete Groups and can open a missing member using its exact installed desktop entry. Once both apps are open in adjacent single-window columns, choose **Rejoin Group** in the switcher. A pinned Group can be rejoined when its apps are at the end of the strip; the pin and saved member order are retained. Duplicate windows, apps on other workspaces, non-adjacent apps and incompatible pin arrangements require manual attention. Saving and restoring a session is blocked while any Group is side by side or has an interrupted layout change; return Groups to a stack first. A new app can open between a side-by-side Group's windows. Flow retains the Group record and offers **Repair Group layout** when both members and the intervening windows are uniquely identifiable, tiled and safe to move around. The repair moves one Group column next to the other, shifting intervening unpinned, ungrouped columns; other arrangements require manual attention. Interrupted transitions are reported with a **Finish layout change** action when both members are available. To remove a Group, reopen and stack both members, unpin it if necessary, and choose **Dissolve Group**. Groups require two distinct, uniquely identifiable apps; automatic adaptive Groups are not supported yet. Flow does not save unsaved documents, app-specific internal state, terminal processes, other workspaces or multiple displays. Apps without a matching desktop entry or with ambiguous windows require manual recovery. Never treat the snapshot as a backup of files. A cold VM boot restored three uniquely identifiable apps and a two-window stack; a warm reboot hung in UTM and required a forced stop.

## Experimental application menu

Open the Desk with `Super+H`, choose **Settings**, and enable **Experimental application menu**. The preference is off by default and saved per user in `$XDG_CONFIG_HOME/flow-settings.ini` (normally `~/.config/flow-settings.ini`). With a work window focused, use the top-left app button or `Super+M` to open its commands. Navigate with Tab and Enter or Space; Escape closes the menu.

Flow reads and invokes the focused application's exposed AT-SPI accessibility menu. It enables the user session's accessibility status when first used and leaves it enabled when the switch is turned off so other accessibility tools are not disrupted. Applications that do not expose a compatible menu show a fallback; their own menus remain available. Multiple windows sharing an application process are treated as ambiguous and also fall back. Menu coverage and responsiveness depend on the application; keyboard shortcut labels, checked states, desktop menu-bar layout and command search are not yet implemented. This experiment has been exercised with Kate, not every app toolkit.

While an app menu is open, a change of focused window or closure of its app keeps the displayed menu in place and disables its commands until the menu is closed. Command invocation also checks the focused window. Focus changes and command routing were exercised with KWrite and Kate in a two-window Group in the ARM64 VM; window closure and other toolkits still need interactive tests.

Pins currently work on one active display and its focused Niri workspace, with unique app IDs. They are stored per user in `$XDG_STATE_HOME/flow/spaces.json` (normally `~/.local/state/flow/spaces.json`). Flow keeps open pinned spaces at the left in saved order. While a side-by-side Group is present on the workspace, pin creation, reordering, and some stack and Group edits are paused to avoid moving one of its columns independently. To pin a Group, first create it from an active two-app stack, then use **Pin Group** in the switcher or focus either member and choose **Pin current space**. The switcher can also unpin it. A Group pin focuses the existing Group as one destination in either supported layout, returning to its last observed focused member. If both members are uniquely identified in adjacent columns at the end of the workspace, session recovery can rebuild the pinned Group without unpinning it. Other missing, ambiguous or separated layouts require manual recovery; where needed, unpin the Group before rebuilding it, then pin it again. If a reopened member has already been rejoined to the stack, Flow can rebind the existing pin when both apps are unique. A missing single-app pin can open its exact installed desktop entry; app-specific state is not restored. Flow cannot reserve a position for an absent app or handle multiple displays yet. Pin ordering is reconciled periodically and can briefly move focus.

Quick Settings offers **Toggle on-screen keyboard** and **Choose Wi-Fi network**. The keyboard can also be toggled with `Super+Shift+K`; it is manual rather than appearing automatically in text fields. The Wi-Fi control opens GNOME's NetworkManager-backed settings panel; **Edit connections** remains available. A real Wi-Fi adapter, physical touch, keyboard shortcuts from the virtual keyboard, and portrait use still need testing.

## Check and build

From this checkout, with flakes enabled:

```sh
python3 -B -m unittest discover -s tests -v
nix build .#checks.aarch64-linux.spaces
nix flake show
# In a running graphical session with a default audio output:
quickshell -p "$PWD/tests/audio-probe.qml"
nix eval .#nixosConfigurations.test.config.system.build.toplevel.drvPath
nix build .#nixosConfigurations.test.config.system.build.toplevel
```

The `test` configuration is an **evaluation/build fixture**, not an installable image: it has a placeholder root filesystem, no configured user and no bootloader. Build on ARM64 Linux or configure a suitable remote builder; a macOS ARM64 host cannot execute Linux build steps by itself. After changing the lock file, rebuild and re-run the guest checks. No passwords or private state are included.

If a VM build reports `No space left on device` despite free disk capacity, check `df -i /` as well as `df -h /`: the filesystem can run out of inodes. On the test guest, `sudo nix-store --optimise` recovered inodes by deduplicating Nix store files while retaining system generations. It can take several minutes and cause disk activity.
